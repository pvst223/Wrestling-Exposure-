## Developer comments (recorded, nothing changed)
1. **Holdout-gate disagreement: conceded in part.** My gate answered NO because pre-registered criterion 7 (no systematic undetectable silent-wrong class) is not met. The auditor separates "trusted as a measurement system" (NO) from "ready for a frozen, unchanged diagnostic test on unseen footage" (YES). The spec's question was the second one, so the auditor's reading fits the wording better than mine, and I accept it as a better framing. My criterion-7 failure stands as a recorded limitation; the original HOLDOUT_READINESS.md is left as written (not edited retroactively). Operationally the two answers agree on what matters: the holdout is the only way to test absorbed-state generalisation, and results must be treated as exploratory diagnostics, not validation.
2. **Caveats the holdout must carry:** one clip, one non-independent reviewer, in-sample-fitted absorption rule; a clean holdout result would not show generalisation, and a bad one would be informative, not a reason to tune on that clip.
3. **Per-clip inputs are not frozen yet:** V0.5 needs manual identity seeds (A, B, referee) and a clip-specific cut log produced by the unchanged detector, plus new segmentation/embedding caches generated by the unchanged scripts and model weights. Seed choice for a new clip should be fixed and written down BEFORE any holdout output is viewed. This is an input, not a code change, but it is a degree of freedom to record.
4. **Appearance cues were built around the development clip** (denim, skin tone). A different wrestler may fail these cues; that is a legitimate holdout finding.
5. The 150-frame persistence constant remains a developer convention (auditor agrees); the major carry sequence cleared at ~41 frames, so the headline result does not depend on it, but other scenes might.
