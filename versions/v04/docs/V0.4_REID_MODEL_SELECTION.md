# V0.4 appearance/ReID model selection (written BEFORE implementing the tracker)

Status: development document. Nothing here is validated against ground truth. Written 2026-10-14 before `track_v04.py` existed.

## 0. What I was asked for, and what I could actually obtain
The specification asks for a stronger person re-identification / appearance representation and warns "do not assume a model is appropriate simply because it is called ReID". **I could not obtain a person-ReID model.** Reachability test from this workspace (HTTP probes, same day):

So V0.4's "ReID-style" representation is **not** a ReID model. It is a general-purpose image embedding, used the way a ReID embedding would be used (gallery of manually seeded exemplars, cosine similarity). That is a substantive limitation, stated here and everywhere downstream.

## 1. Selected model/method
**MobileCLIP-B image encoder** (Apple, Vasu et al. 2024; ViT-B/16, 224x224 input, 512-d output, 86.3 M image-tower parameters). Weights: the image tower inside Ultralytics' TorchScript export `mobileclip_blt.ts` (sha256 `a67804d1b0f07b8b9a20c1761ec0847f34660f5fa338ec70e8f3fce68ed95e54`, 599,764,649 bytes, downloaded from `github.com/ultralytics/assets/releases/download/v8.3.0/`). The TorchScript file has the text tower traced but the image tower reduced to a state dict (no forward), so the image tower was rebuilt from Apple's open architecture code (`apple/ml-mobileclip` commit `48faa0fea4b08d74188b3841771aca6ff2c92852`, MIT code licence, vendored under `src/third_party/mobileclip`) and loaded with `strict=True` (163/163 keys matched, 0 missing, 0 unexpected). Model licence for the weights is Apple's separate model licence (see the repo's `LICENSE_MODELS`); I have not verified that it permits your intended use, you should.

Usage: three letterboxed crops per candidate detection, cut from that candidate's own pose keypoints (no segmentation exists):
* BOX: the detection box.
* UPPER: bbox of confident head/shoulder/hip keypoints (both shoulders and >= 4 of 5 points required).
* LOWER: bbox of confident hip-to-ankle keypoints (>= 3 of 6 including a knee).
Each crop yields an L2-normalised embedding. Identity evidence = cosine similarity to the embeddings of the **10 manually seeded crops** (A: 4, B: 4, referee "NEITHER": 2), compared per crop type. No online adaptation, no fine-tuning.

## 2. Why it is (and is not) appropriate for this footage
Reasons it is plausible: it encodes clothing texture/pattern and global appearance, not only colour statistics, and it runs on CPU. A seed-only leave-one-out check I ran before building anything (10 seed crops, 3-class nearest-prototype by mean cosine similarity): BOX 9/10 correct, UPPER 8/10, LOWER 7/10, thighs 10/10 (thigh crop is not used in V0.4; it was only a probe). Mean pairwise cosine *distance* did **not** separate the wrestlers cleanly (box: A-A 0.157, B-B 0.144, A-B 0.202; upper: A-A 0.270, B-B 0.170, A-B 0.256), so the signal is weak and sensitive to pose/crop layout. This is 10 crops from 5 frames; it is a sanity probe, not an accuracy estimate.
Reasons it may be inappropriate: it was trained for image-text matching, not to be invariant to pose, viewpoint and occlusion of *the same person*; it can encode background and the opponent in the crop; wrestlers in similar attire would be near-identical.

## 3. Pretrained domain
Contrastive image-text pretraining on DataCompDR (web-scale image-caption pairs, general content). No wrestling data, and no person-identity supervision. Not trained on MSMT17/Market/DukeMTMC as ReID models are.

## 4. Input requirements
RGB crop, letterboxed to 224x224 (grey padding 114), values scaled to [0,1], no mean/std normalisation (as in MobileCLIP's published transforms). Minimum crop side 24 px before resizing (smaller crops are not embedded). Source video is 640x360 so many upper/lower crops are heavily upsampled.

## 5. CPU/runtime implications
Measured on this 2-core workspace: about 0.27 s per crop (batch 8, fp32). The development clip has 3,426 gated candidate detections, about 8,500 crops, about 40 min one-off. Embeddings are cached to `cache/embeddings_mobileclip_b.npz` and the tracker reads the cache, so the tracker itself runs in seconds. The 600 MB weights file is not included in the package (hash + download URL + procedure are); the cache is included.

## 6. Known limitations (wrestling-specific)
Not trained to handle: grounded/bent poses (crop layout changes the embedding), partial bodies (upper-only close-ups produce an UPPER crop but no LOWER), two bodies in one crop (the embedding mixes them), crowd/background content, motion blur, low resolution. Seed-derived reliability is based on 10 crops, so it is a coarse number. A and B were chosen by me by eye. The referee class has only 2 seed crops.

## 7. Calibration
**Cosine similarity is an uncalibrated heuristic similarity, not a probability, and not a calibrated distance.** V0.4 converts it to a bounded "support" in [-1, 1] by dividing the similarity margin (vs the other wrestler and vs the referee) by a scale derived from the seeds' own leave-one-out margins, and sets a reliability equal to max(0, 2·LOO-accuracy − 1) times a crop-size factor. Both are provisional heuristics. They are not fitted to the benchmark and not validated.

## 8. What would change this selection
A person-ReID model trained on a large ReID corpus (e.g. OSNet / TransReID-class) with weights that can be obtained and checked, evaluated on independent labels from footage that was not used for design. None was available.
