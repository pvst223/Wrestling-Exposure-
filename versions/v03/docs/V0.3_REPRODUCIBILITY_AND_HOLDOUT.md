## Holdout protocol (for later; nothing has been run)
V0.3 is clip-agnostic: all clip-specific information is in the seeds file; all behaviour is in `config_v03.json`.
1. Obtain a clip not used in any development step; do not look at V0.3 outputs on it before the protocol is fixed.
2. Detections: run V0.1's `stage1_detect.py` unchanged. Cuts: `cuts_events.py` unchanged.
3. Write a seeds file (frames/detections for A, B, NEITHER) **from frames the reviewer chooses before running**; record exactly what was supplied; exclude seed frames from evaluation.
4. Run `track_v03.py` with the frozen config (its hash must equal the frozen one). Inspect `run_meta_v03.json → appearance_models.gap`: if no region type has gap ≥ 0.15 the appearance cues carry no weight and the system will mostly return UNRESOLVED (that is intended fail-closed behaviour, not a bug).
5. Evaluate with pre-registered metrics: status counts; reason-code breakdown; identity and contamination errors and unnecessary rejections on a random frame sample labelled by a reviewer who did **not** see V0.2/V0.3 overlays (blinded to status); camera-cut precision/recall against independently labelled cuts; off-image predictions.
6. **No change to code, config or seeds after viewing holdout results.** Any change defines a new version and a new holdout.
7. Known limits for the holdout: the denim cue is clothing-specific and calibrated from one seed; appearance models are static; wrestlers with similar clothing will give small gaps; two touching bodies detected as one box remain a failure mode.
